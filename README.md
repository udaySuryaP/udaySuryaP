### [Memoid](https://github.com/udaySuryaP/memoid)

A source-aware context system for AI-native software projects.

The problem I'm exploring is simple: AI tools are increasingly useful while you're working with them, but project knowledge, decisions and implementation context often become fragmented across conversations and tools.

Memoid is being designed around durable project context, provenance, source identity, authorization boundaries, versioned context and controlled updates rather than treating long-term context as a large chat history.

**Current architecture:** TypeScript · Next.js · Fastify · PostgreSQL · Kysely · Docker · MCP

> In active development.

## How I like to build

I care about the parts of software that sit between the mockup and the final deployment:

- turning vague requirements into product flows and system boundaries
- designing APIs and data models before adding complexity
- keeping authentication, authorization and ownership explicit
- building AI features around grounding, retrieval and provenance rather than just prompting
- making interfaces understandable without disconnecting them from the underlying system
- shipping working software and then refining it from real constraints

My design background still influences how I engineer products. I tend to think about the user flow, the system model and the implementation together rather than treating them as separate stages.
